# PRD：移动端顶部栏、二级菜单抽屉与个人中心页

## Problem Statement

在 `jcloud` 移动端，用户点击底部 Tab 时只能进入对应一级模块的第一个二级菜单页面，进入后没有 UI 可以切换到该模块下的其他二级页面。例如点击「系统」后只能停在「用户管理」，无法前往「角色管理」或「权限管理」。

同时，移动端没有任何区域展示应用 Logo，也没有任何入口查看当前登录用户信息、修改个人资料、修改密码或退出登录。这使得移动端体验不完整，用户容易迷失上下文。

## Solution

为移动端设备外壳（Mobile Device Shell）增加一个固定的移动顶部栏（Mobile Header）。顶部栏左侧展示品牌图标，中间展示当前一级模块（Primary Module）标题，右侧展示当前用户头像。点击模块标题会从左侧滑出移动侧边抽屉（Mobile Drawer），列出当前一级模块下的全部二级菜单（Secondary Menu）。点击头像则进入独立的个人中心页（Profile Page）。

底部 TabBar 的高亮状态不再只匹配第一个二级菜单路由，而是根据当前路由反向解析到所属一级模块，确保在任意二级页面下 Tab 高亮都正确。

个人中心页复用 PC 端已有的个人信息与修改密码弹窗，并将它们迁移到共享组件目录，避免为移动端重复实现相同逻辑。

## User Stories

1. 作为移动端用户，我希望在顶部看到应用 Logo，以便确认自己正在使用 `jcloud`。
2. 作为移动端用户，我希望点击底部 Tab 能进入对应一级模块的默认二级页面，以便在「文件」与「系统」之间快速切换。
3. 作为移动端用户，当我处于某个二级页面（如「角色管理」）时，我希望所属一级模块（系统）的底部 Tab 保持高亮，以便始终知道当前所处的一级上下文。
4. 作为移动端用户，我希望点击顶部当前模块标题后，能看到该模块下的所有二级页面入口，以便进入「用户管理」「角色管理」「权限管理」等页面。
5. 作为移动端用户，我希望在二级菜单抽屉中选中某个页面后抽屉自动关闭并导航到目标页，以便顺畅地继续操作。
6. 作为移动端管理员，我希望「系统」抽屉中完整展示「用户管理」「角色管理」「权限管理」，以便管理所有后台功能。
7. 作为移动端普通用户（仅有 `user:menu` 权限），我希望「系统」抽屉只展示「用户管理」，以便不会看到无权限访问的页面。
8. 作为移动端用户，我希望点击顶部头像进入个人中心页，以便查看和操作与账号相关的内容。
9. 作为移动端用户，我希望个人中心页展示我的用户名、昵称、邮箱和角色，以便核对账号信息。
10. 作为移动端用户，我希望在个人中心页点击「个人信息」后弹出编辑弹窗，以便更新昵称和邮箱。
11. 作为移动端用户，我希望在个人中心页点击「修改密码」后弹出修改密码弹窗，以便定期更换登录密码。
12. 作为移动端用户，我希望在个人中心页能退出登录，以便安全地切换账号。
13. 作为移动端用户，当我位于个人中心页时，我希望左上角显示返回箭头而不是 Logo，以便返回之前的页面。
14. 作为移动端用户，我希望在滚动长内容时顶部栏始终固定，以便随时访问导航和个人入口。
15. 作为移动端用户，我希望在滚动长内容时底部 TabBar 始终固定（除非页面明确隐藏），以便随时切换一级模块。
16. 作为移动端用户，我希望二级菜单抽屉从左侧滑出，并带有遮罩层，以便符合常见的移动端交互习惯。
17. 作为移动端用户，我希望当前选中的二级菜单在抽屉中有视觉高亮，以便一目了然地知道自己所在页面。
18. 作为开发者，我希望个人信息弹窗和修改密码弹窗能被 PC 端和移动端共用，以便降低维护成本。
19. 作为开发者，我希望路由到一级模块的解析逻辑是可单元测试的，以便在新增模块或路由时保证导航状态正确。
20. 作为移动端用户，我希望点击 Logo 图标能快速回到「文件」首页，以便有一个稳定的逃生出口。

## Implementation Decisions

### 1. 移动设备外壳增加固定顶部栏

- 在移动端设备外壳中，于主内容区上方插入一个固定高度的移动顶部栏。主内容区继续通过 `flex-1 overflow-y-auto` 独立滚动，顶部栏与底部 TabBar 保持固定。
- 顶部栏高度与 PC 端顶部导航栏保持一致，维持视觉统一。

### 2. 顶部栏职责划分

- **左侧**：品牌图标（仅图标，不展示文字），点击后返回 `files` 模块的第一个二级页面。
- **中间**：当前一级模块名称，点击后打开左侧二级菜单抽屉。
- **右侧**：当前用户头像，点击后导航到 `/profile`。

### 3. 二级菜单抽屉

- 抽屉从左侧滑出，覆盖主内容区，并带有半透明遮罩；点击遮罩或选中菜单项后关闭。
- 抽屉内容基于 `menuStore.getSecondaryMenusByPrimary(activePrimary)` 动态生成，因此权限变化会自动反映到菜单列表。
- 当前路由对应的二级菜单项需要高亮显示。

### 4. 底部 TabBar 高亮逻辑

- 底部 TabBar 的条目继续代表一级模块，点击后跳转到该模块的第一个二级页面。
- 高亮状态通过遍历所有一级模块的二级菜单，查找当前路由所属的一级模块得出；不再依赖 `route.path.startsWith(tab.route)`。
- 当路由属于个人中心页等不属于任何一级模块的页面时，底部 TabBar 不强制高亮任何 Tab，或保持上一个有效状态。

### 5. 个人中心页

- 新增一个不属于任何一级模块的顶层路由 `/profile`，由移动端视图渲染。
- 个人中心页展示用户基本信息（用户名、昵称、邮箱、角色），并提供「个人信息」「修改密码」「退出登录」三个操作入口。
- 在个人中心页中，移动顶部栏左侧显示返回箭头，标题固定为「个人中心」，不展示模块标题抽屉入口。
- 返回箭头调用 `router.back()`，让用户回到进入个人中心前的页面。

### 6. 弹窗组件复用与迁移

- 将 `ProfileDialog` 与 `ChangePasswordDialog` 从 PC 专用目录迁移到共享组件目录，供 PC 端 Header 与移动端个人中心页共同引用。
- 弹窗内部表单、校验、API 调用逻辑保持不变；移动端通过页面按钮触发弹窗的打开与关闭。

### 7. 状态与 API 复用

- 顶部栏和个人中心页继续使用 `useUserStore` 获取当前用户信息与执行退出登录。
- 个人信息的读取与更新继续使用现有的用户资料 API。
- 不需要新增后端接口或数据库变更。

### 8. 样式规范

- 所有新增组件必须使用 Tailwind CSS 类名实现，禁止使用标准 `<style>` 标签。
- 动态类名拼接必须使用项目中的 `cn` 工具函数。
- 移动端顶部栏与抽屉应使用与现有设计系统一致的颜色变量（如 `surface`、`primary` 系列）。

## Testing Decisions

### 测试缝（Seam）

本次变更的核心逻辑缝是 **路由到一级模块的解析逻辑**。底部 TabBar 的高亮、抽屉标题的显示、抽屉中二级菜单的生成，全部依赖于「给定一个路由，知道它属于哪个一级模块」这一判断。

因此，推荐的测试缝是 `menuStore` 中负责路由解析与二级菜单生成的逻辑（或从中抽取的纯函数）。

### 测试策略

- 新增前端单元测试，使用 Vitest 对 `menuStore` 的路由解析逻辑进行测试。测试用例覆盖：
  - `/files`、`/files/share`、`/files/trash`、`/files/remote-mounts` 均解析到 `files` 模块。
  - `/admin/users`、`/admin/roles`、`/admin/permissions` 均解析到 `system` 模块。
  - `/profile` 不属于任何一级模块。
  - 在模拟不同权限用户时，`getSecondaryMenusByPrimary('system')` 返回的菜单项正确过滤。
- 对 `useUserStore` 进行 mock，以测试权限相关的二级菜单过滤。
- UI 交互（抽屉动画、顶部栏渲染、个人中心页跳转）通过手动 QA 在移动视口下验证；本项目当前没有前端 E2E 测试基础设施，因此本次 PRD 不引入新的 E2E 测试缝。

### 什么是好的测试

- 只测试外部行为，不测试实现细节。例如测试「给定路由 `/admin/roles`，应解析到 `system` 模块」，而不是测试内部字符串匹配方式。
- 优先测试权限边界和管理员边界，因为系统菜单是权限敏感的。
- 避免对纯 UI 定位做断言，未来 UI 调整不应导致测试大规模失败。

### 相关先例

- 后端 `RoleServiceImplTest`、`UserProfileServiceTest`、`PermissionServiceImplTest` 等项目已有的 JUnit 测试，体现了在 `jcloud` 中对业务逻辑层做单元测试的偏好。本次前端测试将遵循同样的分层测试思路，将导航逻辑视为前端「业务逻辑」进行测试。

## Out of Scope

- `notes` 与 `todos` 一级模块的移动端页面实现。它们已在 `menuStore` 中定义，但本次 PRD 只针对当前已上线的 `files` 与 `system` 模块做导航改造。
- 平板设备的布局调整。根据 ADR 0001，平板继续被视为 PC 端，使用 PC 设备外壳。
- 原生移动端能力（推送通知、生物识别登录、离线缓存等）。
- PC 端顶部导航栏与左侧边栏的重新设计。
- 从个人中心页生成分享链接或深链。
- 头像图片上传功能。

## Further Notes

- 将底部 Tab 保持为一级模块、通过抽屉承载二级菜单的决策，已记录在 `docs/adr/0002-mobile-navigation-redesign.md`。
- 未来新增一级模块时，只需在 `MobileBottomNav` 维护的一级模块列表中添加对应条目，并确保 `menuStore.getSecondaryMenusByPrimary` 返回其二级菜单；顶部栏与抽屉会自动适配。
- 个人中心页应尽量复用现有 API 与弹窗组件，避免在移动端单独维护一份用户资料逻辑。
- 由于本次变更涉及移动端全局布局，建议在合并前至少在一台真实手机或浏览器移动视口下完成端到端手动验证。
