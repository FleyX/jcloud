# PRD：文件管理核心模块

## Problem Statement

JCloud 当前仅实现了用户、角色、权限等基础管理能力，缺少个人网盘最核心的文件管理能力。用户无法上传、浏览、组织、下载、删除或预览自己的文件；管理员也无法为用户分配存储空间、扩容或迁移用户数据。这导致 JCloud 目前无法作为可用的个人网盘产品交付。

## Solution

构建文件管理核心模块，为每位用户提供一棵独立的虚拟文件树，基于镜像存储模型持久化到管理员配置的存储空间。模块覆盖文件与文件夹的上传、浏览、组织、下载、删除、恢复、预览等核心能力，同时提供管理员侧的存储空间管理、用户配额控制、用户迁移等运维能力。

## User Stories

### 上传与传输

1. 作为用户，我希望通过拖拽或选择文件上传，以便将本地文件保存到网盘。
2. 作为用户，我希望上传整个文件夹并保持其目录结构，以便批量迁移本地资料。
3. 作为用户，我希望上传大文件时自动分片，以便在网络不稳定时也能完成上传。
4. 作为用户，我希望上传中断后能够断点续传，以便不浪费已上传的流量和时间。
5. 作为用户，我希望重复上传已存在的文件时能够秒传，以便节省时间和带宽。
6. 作为用户，我希望在上传冲突时选择跳过、覆盖或自动重命名，以便控制文件名冲突的结果。
7. 作为用户，我希望在传输列表中查看所有上传任务的进度、状态（等待中/上传中/已暂停/成功/失败），以便掌握上传情况。
8. 作为用户，我希望能够暂停和继续单个上传任务，以便灵活控制带宽使用。

### 浏览与查找

9. 作为用户，我希望以列表或网格方式查看当前文件夹的内容，以便按习惯浏览文件。
10. 作为用户，我希望通过面包屑导航快速跳转到上级或任意祖先文件夹，以便在目录树中高效移动。
11. 作为用户，我希望按名称、修改时间、大小、类型排序文件，以便快速找到目标文件。
12. 作为用户，我希望默认视图下文件夹排在文件前面并按修改时间倒序排列，以便查看最新内容。
13. 作为用户，我希望通过文件名搜索快速定位文件，以便在文件量增大后高效查找。
14. 作为用户，我希望在 PC 端使用分页浏览，在移动端使用无限滚动，以便在不同设备上获得合适的体验。

### 组织

15. 作为用户，我希望创建新文件夹来归类文件，以便保持目录整洁。
16. 作为用户，我希望重命名文件或文件夹，以便修正命名错误或更新语义。
17. 作为用户，我希望移动文件或文件夹到其他位置，以便重新组织目录结构。
18. 作为用户，我希望复制文件或文件夹，以便快速生成备份或模板。
19. 作为用户，我希望选择多个文件/文件夹进行批量移动、复制或删除，以便提高操作效率。
20. 作为移动/复制操作的用户，当目标位置存在同名文件时，我希望系统提示我选择跳过、覆盖或保留，以避免误操作。

### 删除与回收

21. 作为用户，我希望删除文件或文件夹时它们进入回收站，以便误删后能够恢复。
22. 作为用户，我希望从回收站恢复文件/文件夹到原来的位置，并在原父目录不存在时自动重建目录，以便找回误删内容。
23. 作为用户，当恢复目标位置已存在同名文件/文件夹时，我希望选择跳过、覆盖或自动重命名，以便控制恢复结果。
24. 作为用户，我希望彻底删除回收站中的文件以释放空间。
25. 作为用户，我希望回收站中的文件在 30 天后自动彻底删除，以便空间被自动管理。
26. 作为用户，我希望删除的文件在回收站保留期间仍然占用我的配额，以便配额计算可预测。

### 下载与预览

27. 作为用户，我希望点击文件即可下载到本地，以便离线使用。
28. 作为用户，我希望大文件下载支持断点续传，以便网络中断后能继续下载。
29. 作为用户，我希望下载整个文件夹或多个文件时被打包为 ZIP，以便一次性获取多个文件。
30. 作为用户，我希望小文件夹能够实时打包下载，而大文件夹先生成 ZIP 再下载，以便平衡速度与稳定性。
31. 作为用户，我希望直接预览图片，以便快速查看而无需下载。
32. 作为用户，我希望预览视频和文本文件，以便快速浏览内容。
33. 作为用户，我希望预览图和海报帧按需生成并存放在系统存储空间，而不占用我的个人配额。

### 空间与配额

34. 作为用户，我希望在侧边栏看到自己的已用空间和配额，以便了解剩余容量。
35. 作为用户，当我上传会导致空间不足时，我希望收到明确提示并被告知联系管理员，以便及时扩容。
36. 作为管理员，我希望创建多个存储空间（如 `/data`、`/data1`）并为每个空间设置容量，以便扩展后端存储。
37. 作为管理员，我希望指定一个系统存储空间存放预览图、系统配置和缓存，以便系统数据不占用用户配额。
38. 作为管理员，我希望在创建用户时为其指定默认存储空间，以便该用户的所有文件落在一个空间内。
39. 作为管理员，我希望为每个用户设置配额，以便限制单个用户的存储使用。
40. 作为管理员，当某个用户空间不足时，我希望扩容其所在存储空间或将该用户迁移到另一个存储空间，以便解决问题。
41. 作为管理员，我希望迁移用户时该用户进入只读状态，以确保数据一致性。

### 冲突与并发

42. 作为用户，当我执行上传、恢复、移动或复制时，如果系统检测到同名文件冲突，我希望在两阶段流程中先看到冲突列表再做决定，而不是被静默处理。
43. 作为用户，当我在冲突解决弹窗中超过规定时间未操作时，我希望系统提示我重新预检，以便基于最新状态做选择。
44. 作为用户，我希望同一时间我的写操作被串行化，避免并发的移动、上传等操作导致目录状态不一致。

## Implementation Decisions

### 数据模型

- 使用统一的 `FileNode` 表存储文件与文件夹，通过 `type: 'file' | 'folder'` 区分，避免分表带来的跨表一致性问题。
- `FileNode` 包含 `parent_id`、`path`（祖先 ID 快照，不包含自身 ID）、`path_name`（虚拟文件树完整可读路径）、`name`、`type`、`size`、`storage_key`、`mime_type`、`status`、`deleted_at` 等字段。
- 文件夹是虚拟节点，物理目录在文件写入时由 `存储空间路径 / 用户编码 / files / path_name` 推导。
- 每个用户绑定一个用户存储空间；系统数据（预览图、配置、缓存）存放在独立的系统存储空间，不计入用户配额。

### 存储与路径

- 采用镜像存储模型：物理路径与虚拟路径保持一致，便于直接读取和灾难恢复。
- 用户文件物理路径公式：`存储空间路径 / 用户编码 / files / path_name`。
- 同一用户内的重复文件优先使用硬链接共享物理 inode；硬链接失败时退化为普通复制。
- 不同用户之间不共享物理文件，以简化配额统计和迁移逻辑。

### 上传与秒传

- 分片大小固定为 10MB；每个分片独立计算 hash 用于完整性校验。
- 断点续传通过预上传检查已存在分片实现，客户端只上传缺失分片。
- 秒传为同一用户内去重。
- 文件身份 hash 策略：小于 150MB 计算完整 hash；大于等于 150MB 取前 50MB、中间 50MB（从 `floor(size/2)` 开始）、后 50MB 拼接后计算 hash，用于快速候选查找。
- 当候选匹配时，必须使用完整文件 hash 做最终校验，防止部分 hash 碰撞导致数据污染。
- 上传前预占用户配额，使用独立的 `reserved_space` 字段；上传完成后转为实际已用空间；失败或取消时释放预留。
- 上传时同时检查用户配额和所属存储空间容量，任一不足则拒绝并提示联系管理员。

### 冲突解决

- 上传、恢复、移动、复制采用两阶段冲突解决流程：预检返回冲突列表 → 用户选择每项策略 → 执行阶段按策略处理。重命名、创建文件夹同名时直接报错。
- 冲突处理选项：跳过、覆盖、保留（格式为 `name(n).ext`）。
- 预检阶段不持锁；执行阶段获取 Redisson 用户写锁。用户决策期间目录状态可能变化，执行时按最新状态重检并按策略兜底。
- 恢复时若原父目录不存在，自动创建缺失文件夹，恢复后路径与删除前保持一致。
- 文件夹冲突时默认递归合并，不进入冲突列表。

### 删除与回收站

- 删除文件/文件夹时移入用户级回收站，物理文件原位保留。
- 回收站保留期为 30 天，到期自动彻底删除。
- 回收站中的文件继续占用用户配额，直到被彻底删除。
- 恢复操作按原路径还原，文件冲突时进入两阶段冲突解决，文件夹冲突时递归合并。

### 移动、重命名与复制

- 移动/重命名文件夹会触发所有后代 `path_name` 的异步级联更新。
- 异步级联更新任务在整个执行期间持有该用户的 Redisson 写锁，防止并发写导致路径不一致。
- 复制操作创建源文件/文件夹的副本，目标路径冲突时进入两阶段冲突解决。
- 文件夹移动/重命名过程中标记 `moving` 状态，便于前端展示和崩溃后恢复。

### 并发控制

- 引入 Redisson 实现分布式读写锁（当前 POM 中尚未引入 Redisson，需要新增依赖）。
- 每个用户的写操作串行化：多个读可并发，写操作互斥。
- 用户存储空间迁移、回收站清空、清空等管理员操作也复用该锁。
- 服务启动时扫描 `moving` 状态记录，根据任务状态决定重试或回滚。

### 浏览与搜索

- PC 端文件列表使用传统分页；移动端使用无限滚动。
- 默认排序：文件夹优先，按修改时间倒序。
- 支持按名称、修改时间、大小、类型排序。
- 列表视图不显示文件夹大小；详情面板可异步计算文件夹大小。
- 文件名搜索基于 PostgreSQL trigram/GIN 索引实现，仅搜索文件名。

### 下载

- 单文件下载采用流式读取，支持 HTTP `Range` 请求实现断点续传。
- 多文件/文件夹下载：总大小或文件数低于阈值时实时打包 ZIP 流式返回；超过阈值时后台预生成 ZIP 文件，生成完成后提供下载。

### 预览

- 图片、视频海报帧、文本预览按需生成，结果存放在系统存储空间。
- 预览文件不计入用户配额。
- MVP 阶段 Office/PDF 渲染不作为内置预览支持。

### 权限与资源

- 新增文件模块相关权限资源（如 `files:menu`、`file:upload`、`file:delete` 等）并注册到 `t_resource` 和 `t_permission_resource`。
- 文件接口统一前缀建议为 `/jcloud/api/files/**`。

### 依赖与配置

- 后端需要新增 Redisson 依赖以支持分布式读写锁。
- 当前 multipart 配置为 `max-file-size=10MB`、`max-request-size=100MB`，需要调整为支持分片上传模式（分片本身 10MB，但一次请求可携带多个分片或元数据）。
- 前端可复用并扩展现有 `transferStore` 来管理上传任务队列、分片进度、暂停/恢复/错误重试。

## Testing Decisions

### 主 Seam：后端 Controller/Service 集成测试

- 沿用项目现有 `@SpringBootTest` + `@Transactional` + `test` profile 模式。
- 测试类位于 `app/src/test/java/com/fleyx/jcloud/` 下，建议优先覆盖 `FileController` 或 `FileService` 的完整文件生命周期。
- 测试中使用 `@TempDir` 或临时目录作为用户存储空间和系统存储空间，避免污染真实磁盘。
- 覆盖场景包括：
  - 文件/文件夹 CRUD
  - 分片上传与断点续传
  - 秒传去重（用户内）
  - 上传/移动/复制/恢复时的冲突解决
  - 配额与存储空间容量限制
  - 删除、回收站、恢复、自动清理
  - 文件夹移动/重命名的异步级联更新
  - 下载（单文件 Range、文件夹 ZIP）
- 测试应关注外部行为（接口返回、数据库状态、磁盘文件存在性、配额变化），而不是内部实现细节。

### 次 Seam：前端文件视图组件测试

- 沿用现有 Vitest + Vue Test Utils + jsdom 模式。
- 测试 `views/pc/files/index.vue` 和 `views/mobile/files/index.vue`。
- 文件 API 通过 `vi.mock('@/api/file')` 完全模拟，不依赖后端服务。
- 覆盖场景包括：
  - 列表/网格渲染与排序
  - 面包屑导航
  - 文件选中与批量操作
  - 右键菜单/操作按钮触发
  - 上传器打开与冲突弹窗展示
  - 传输列表状态变化

## Out of Scope

- 跨用户文件共享与协作编辑。
- 公开链接分享（分享模块不在本次核心模块范围内）。
- 文件版本历史。
- 文件内容全文搜索（本次仅支持文件名搜索）。
- Office/PDF 等复杂格式的内置渲染预览。
- 客户端加密与端到端安全。
- CDN、分布式对象存储、远程挂载。
- 移动端离线同步与本地缓存。
- 跨存储空间的去重（同一用户跨空间复制时按普通复制处理）。

## Further Notes

- 当前代码库中尚未有任何文件管理相关实体、表、控制器、Service 或前端 API，需要从 0 开始构建。
- `UserContext` 已包含当前登录用户的 `userCode`，文件模块可直接复用。
- `transferStore` 已存在并管理上传任务队列，但当前为 Mock 状态，需要扩展分片进度、暂停/恢复、错误重试等字段。
- 文件模块的 Flyway 迁移建议作为独立迁移文件（如 `V5__file_management.sql`）新增，包含 `t_storage_space`、`t_file_node`、`t_file_chunk`、`t_recycle_bin` 等表，以及对 `t_user` 的配额/存储空间扩展。
- 管理员迁移用户时，该用户所有字节从源存储空间复制到目标存储空间；迁移期间用户只读，完成后切换用户绑定的存储空间。
- 由于物理文件路径依赖 `path_name` 快照，所有会导致路径变化的操作（重命名、移动、恢复）都必须级联更新后代 `path_name`，或触发异步任务完成。
