# PRD：影视收藏、顶栏影视菜单与类型页

## Problem Statement

影视模块当前是「Jellyfin 风单页导航」：无模块级菜单，媒体库之间、库与首页之间靠页面内自绘的返回按钮穿梭，缺少统一的导航框架。用户无法标记喜欢的影片（全系统无收藏能力），无法按评分/标题排序海报墙，无法按类型（Genre）浏览库内容；库级维护操作（扫描、削刮）藏在目录管理页，日常刷新元数据不方便。此外，海报卡片与详情页的「不完整」标记对用户噪音过大，电影详情页单版本时版本列表冗余。

## Solution

为影视模块增加模块级**顶栏影视菜单**（PC 与移动端均渲染），承载首页/我的收藏/库内各 Tab 与搜索、排序、配置入口；新增**收藏**能力，覆盖电影、剧集、季、集、其他条目五类实体；新增**我的收藏页**与**类型页**；媒体库卡片增加悬浮**库卡片菜单**，把扫描与两档元数据刷新放到首页触手可及处；同时移除「不完整」标记、单版本电影隐藏版本列表。

## User Stories

1. 作为用户，我希望在电影海报卡片上鼠标移入时点心形即可收藏，以便不打断浏览就标记喜欢的影片。
2. 作为用户，我希望在电影/剧集详情页有点收藏按钮，以便在看完简介后顺手收藏。
3. 作为用户，我希望剧集详情里季卡片和每一集也能收藏，以便标记特别喜欢的某一季或某一集。
4. 作为用户，我希望其他库的条目同样可以收藏，以便标记喜欢的非影视视频。
5. 作为用户，我希望取消收藏只需再次点击心形，以便随时反悔。
6. 作为用户，我希望影视首页顶栏有「首页 / 我的收藏」两个居中的 Tab，以便一键查看我的所有收藏。
7. 作为用户，我希望我的收藏页按实体类型分区（电影/剧集/季/集/其他）展示、区内按收藏时间倒序，以便快速找到刚收藏的内容。
8. 作为用户，我希望收藏页点击电影/剧集/季/集卡片跳到对应详情页（集跳剧集详情并定位到对应季）、点击其他条目直接播放，以便从收藏直达内容。
9. 作为用户，我希望空的分区不显示，以便页面不出现无内容的占位。
10. 作为用户，我希望进入媒体库后顶栏出现「我的收藏」Tab，只看这个库里的收藏，以便聚焦当前库。
11. 作为用户，我希望进入媒体库后顶栏有「类型」Tab，看到该库所有类型的卡片网格，以便按动作、喜剧等类型浏览。
12. 作为用户，我希望点击类型卡片后进入该库该类型的筛选海报墙，以便只看这一类影片。
13. 作为用户，我希望其他库不显示「类型」Tab，因为它没有元数据类型概念。
14. 作为用户，我希望库详情页顶栏右侧有排序图标，点击弹窗选择排序字段（添加时间/发行时间/评分/标题）与升降序，以便按更多维度浏览。
15. 作为用户，我希望排序选择被记住（按库区分），以便下次进入保持我的偏好。
16. 作为用户，我希望影视首页顶栏右侧有全局搜索图标，跨所有媒体库搜索并按电影/剧集/其他分组展示结果，以便不记得到底在哪个库也能找到影片。
17. 作为用户，我希望在库详情页点搜索只搜当前库，以便结果不被其他库干扰。
18. 作为用户，我希望顶栏右侧有配置图标直达目录管理页，以便管理媒体库来源目录。
19. 作为用户，我希望进入电影/剧集详情页时顶栏影视菜单消失，以便沉浸查看详情；返回后菜单恢复。
20. 作为移动端用户，我希望顶栏影视菜单在手机上同样可用（Tab 可横滑、图标保留），以便移动端也能用收藏、排序、类型功能。
21. 作为用户，我希望影视首页的媒体库卡片鼠标移入时右下角出现菜单按钮，以便对库做维护操作。
22. 作为用户，我希望库卡片菜单里能选「扫描媒体库」（扫描新增/变更文件，完成后自动非强制削刮），以便新增影片后一键入库。
23. 作为用户，我希望库卡片菜单里能选「刷新缺失元数据」（非强制削刮），以便补齐未匹配或不完整的条目而不动已匹配数据。
24. 作为用户，我希望库卡片菜单里能选「强制刷新所有元数据」（强制削刮所有非 manual 行），以便获取 TMDB 最新元数据。
25. 作为用户，我希望其他库的卡片菜单只有「扫描媒体库」，以便界面不出现对无元数据库无意义的选项。
26. 作为用户，我希望海报卡片和详情页不再显示「不完整」标记，以便界面干净（「未识别」标记保留，因为它引导我去修正匹配）。
27. 作为用户，我希望单版本电影详情页不显示版本列表、点播放直接播该版本，以便页面不冗余。
28. 作为用户，我希望已被删除（含扫描清理、取消挂载）的条目的收藏记录随之消失，以便收藏页不出现死条目。
29. 作为管理员，我希望 TMDB 配置与转码配置仍只在系统菜单的影视设置页，以便顶栏配置图标面向所有用户只提供目录管理。

## Implementation Decisions

### 1. 收藏数据模型（新表 `t_media_favorite`）

```sql
id          -- 主键，13 位 base36（项目既有约定）
user_id     -- 收藏者，按用户隔离
owner_type  -- movie / series / season / episode / other（枚举，与元数据 owner_type 对齐 + other）
owner_id    -- 对应实体主键
create_time -- 收藏时间，收藏页按此倒序
唯一约束：(user_id, owner_type, owner_id)
```

- 无实体外键（项目禁用外键），级联清理由应用层负责：电影/剧集/季/集/其他条目的各级联删除路径（批次清理、增删来源目录清空、取消挂载级联、手动删除媒体库）均需按 `owner_type + owner_id` 删除收藏记录。用户删除路径不做收藏清理：管理员删除用户（UserServiceImpl.removeById / UserAdminSupport.batchDelete）现状不清理任何媒体数据，媒体行本就按用户隔离残留，收藏与之一致。
- 收藏与匹配状态无关：未识别条目也可收藏。

### 2. 收藏 API

- `POST /media/favorites/toggle`，入参 `{ownerType, ownerId}`，返回切换后的 `favorited` 布尔——心形按钮一处调用，幂等友好。
- 既有海报墙/详情/季列表/集列表接口的 VO 增加 `favorited` 字段（按当前用户联查填充），避免前端逐条查询状态。
- `GET /media/favorites?directoryId=&ownerType=&page=&size=`：我的收藏页数据。首页入口不传 `directoryId` 查全部；库内入口传库 ID 只查该库。响应按五类实体分区，每区含条目列表（海报墙卡片所需的现有字段 + `favorited`）与总数，支持按 `ownerType` 独立分页（首屏每区一页，滚动加载调同接口）。
- 收藏条目复用现有展示逻辑：电影/剧集/季/集用海报卡，其他条目用截图缩略图卡。

### 3. 顶栏影视菜单

- 新增共享组件（PC/移动端共用，移动端 Tab 可横向滚动），由影视主页与媒体库详情页各自渲染；电影/剧集详情页、独立播放页不渲染——因此菜单天然不出现在详情页，也无需外壳层改动。
- 路由结构不变，Tab 状态用路由 query（`?tab=favorites|genres`）承载，刷新/分享链接可还原。
- 影视主页菜单：居中「首页 / 我的收藏」；右侧全局搜索图标 + 配置图标（跳既有目录管理页）。首页既有「目录管理」按钮移除。
- 媒体库详情页菜单：居中「{库类型名：电影/剧集/其他} / 我的收藏 / 类型」；右侧库内搜索图标、排序图标、配置图标。其他库不渲染「类型」Tab。墙页既有返回按钮+库名头部移除，由顶栏取代。
- 全局搜索：`GET /media/search?keyword=`，跨该用户全部媒体库搜索（搜索字段与现有墙内搜索一致：文件名/剧名/元数据标题/简介），响应按电影/剧集/其他分组，各组前 N 条 + 总数；点击结果进对应详情页（其他条目直接播放）。库内搜索复用既有搜索弹窗与接口。

### 4. 排序扩展

- 海报墙查询 `sortField` 枚举扩展：电影/剧集支持 `added`（添加时间）/ `release`（发行时间）/ `rating`（评分，`vote_average`，NULLS LAST）/ `title`（标题，元数据标题优先、无元数据回退条目名称）；其他库支持 `added` / `title`（条目名称）。
- 排序 UI 从工具条双按钮改为弹窗：字段单选 + 升/降序单选；选择继续按墙记忆 localStorage（既有机制，key 不变）。
- 弹窗作用于主墙与类型筛选墙；我的收藏分区页固定按收藏时间倒序，不参与排序。

### 5. 类型页

- `GET /media/libraries/{id}/genres`：聚合该库电影行/剧集行元数据的 `genres` 字段（逗号分隔存储，聚合时拆分），返回类型列表，每项含名称、条目数、一张代表海报（取该类型下任一条目海报）。
- 类型页渲染类型卡片网格（封面用代表海报）；点击进入该库主墙并带 `genre` 筛选参数——墙查询接口增加可选 `genre` 入参（匹配元数据 genres 包含该值），类型筛选墙与主墙共用组件与分页。
- 仅电影/剧集库可用；季、集的类型不单独聚合（集元数据派生自剧，天然同类型）。

### 6. 库卡片菜单

- 影视首页媒体库卡片（含我的媒体分区）右下角增加菜单按钮，仅鼠标移入卡片（移动端为点击卡片上的常驻小按钮）时可见；点击弹出悬浮下拉菜单。
- 菜单项全部复用既有接口，无新增后端动作：
  - 「扫描媒体库」→ 既有目录扫描接口（扫描新增/变更文件，完成后自动提交一次非强制削刮，与目录管理页「扫描」按钮语义一致）。
  - 「刷新缺失元数据」→ 既有目录削刮接口（非强制，仅处理未匹配或不完整的非 manual 行）。
  - 「强制刷新所有元数据」→ 既有目录削刮接口 `force=true`（所有非 manual 行重新匹配拉取；manual 行不覆盖）。
- 其他库只显示「扫描媒体库」。触发后沿用既有任务状态提示（扫描/削刮互斥、目录任务锁），前端触发即提示，不阻塞。

### 7. 移除与简化

- 删除海报卡片的「不完整」角标与详情页头部的「不完整」标识（`metadata_complete === false` 的 UI 呈现）；后端完整性重算逻辑保留（削刮补缺判断仍依赖它）。「未识别」角标保留。
- 电影详情页 `versions.length === 1` 时不渲染版本列表，播放按钮直接播放默认版本；多版本行为不变。

## Testing Decisions

- **唯一测试缝：后端 Service 层集成测试**（Spring Boot + application-test.yml + 真实 PostgreSQL），与既有 `MediaItemServiceTest`、`MediaScrapeServiceTest`、`MediaHomeServiceTest` 同模式。前端无测试缝（项目现状无前端测试）。
- 只断言外部可观察行为（接口返回、数据库状态），不断言实现细节。
- 覆盖点：
  - 新增 `MediaFavoriteServiceTest`：toggle 幂等与唯一约束、五类实体收藏、按用户隔离、收藏页分区/分页/库过滤、级联清理（删电影/剧集/季/集/其他条目、增删来源目录、取消挂载后收藏记录消失）。
  - 扩展 `MediaItemServiceTest`：`rating`/`title` 排序（含 NULLS LAST 与无元数据回退）、`genre` 筛选、全局搜索分组与命中字段、VO `favorited` 填充、genres 聚合（逗号拆分、计数、代表海报）。
  - 扩展 `MediaScrapeServiceTest`（如尚未覆盖）：目录级非强制/强制削刮接口被库卡片菜单复用语义的回归。
- 库卡片菜单三个动作均为既有接口，测试重点是前端接线，后端回归即可。

## Out of Scope

- 按钮级权限（按项目约定只做页面权限）。
- 收藏的分享、导入导出、跨设备同步以外的能力；收藏不参与推荐/猜你喜欢。
- 播放页、转码、字幕、削刮匹配逻辑本身的改动。
- 季/集的类型聚合与类型筛选；其他库的类型概念。
- 顶栏影视菜单在文件、系统等其他一级模块的推广。
- 「未识别」标记的移除（保留）。

## Further Notes

- 本 PRD 不修订任何历史 PRD：`docs/prd/` 中既有的 `file-management-core.md` 与 `mobile-navigation-redesign.md` 均不覆盖影视模块行为（顶栏影视菜单是页内导航，不改变移动顶部栏/底部 TabBar 职责）。
- 无新增 ADR：收藏表结构与级联沿用项目既有约定（`t_` 前缀、禁外键、应用层级联、按用户隔离），顶栏菜单为可逆的 UI 决策，未产生需要记录的艰难权衡。
- 领域术语已同步至 `CONTEXT.md`：收藏（Favorite）、顶栏影视菜单（Media Top Menu）、我的收藏页（Favorites Page）、类型页（Genres Page）、库卡片菜单（Library Card Menu）。
- 本 PRD 拆分为 5 张工单实施：01 收藏功能全量（五类实体端到端）、02 顶栏影视菜单+我的收藏页、03 全局搜索+排序扩展、04 类型页、05 库卡片菜单+UI 清理。工单为 `.scratch/` 临时件，完成后不保留。
