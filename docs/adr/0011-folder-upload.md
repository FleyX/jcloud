# 文件夹上传

我们决定支持通过浏览器原生 `<input webkitdirectory>` 选择文件夹并上传，后端负责解析相对路径、自动创建文件夹层级，并复用现有分片上传与秒传能力。

## 背景与取舍

文件管理已支持单文件与多文件上传，但用户经常需要上传一个整理好的文件夹并保持内部层级。直接上传会丢失目录结构，体验较差。

考虑过三种方案：

1. **前端负责创建层级**
   - 前端根据 `webkitRelativePath` 逐层调用 `/files/folders` 创建文件夹，再按最终 `parentId` 上传文件。
   - 优点：后端几乎不用改。
   - 缺点：层级深时请求多、网络失败易留下半拉目录、冲突处理分散、性能差。

2. **后端提供批量创建文件夹映射**
   - 前端先调用接口批量创建文件夹结构，拿到 `relativePath → parentId` 映射，再复用现有上传能力。
   - 优点：利用现有上传逻辑。
   - 缺点：两次交互，文件夹多时也慢，且无法原子化。

3. **扩展现有分片上传以支持相对路径（选定）**
   - 在 `/files/upload/pre-check` 和 `/files/chunked-upload/init` 中增加 `relativePath` 字段，后端自动解析路径、创建或复用文件夹，并返回/使用最终目标目录。
   - 优点：大文件仍走分片；秒传逻辑可复用；路径创建与上传流程内聚；用户级写锁保证并发安全。
   - 缺点：需要改动预检与初始化两个接口。

选择方案 3。

## 关键决策

### 1. 入口形态

- 保留 PC 端文件列表工具栏的「上传」下拉菜单。
- 「上传文件」保持原有行为，选择多个文件并上传到当前目录。
- 「上传文件夹」使用独立的 `<input type="file" webkitdirectory>`，选择文件夹后上传其全部内容。
- 删除原「离线下载（占位）」菜单项。

### 2. 相对路径语义

- `relativePath` 包含文件名，与浏览器 `File.webkitRelativePath` 原生格式一致，例如 `project/src/main.java`。
- 目录部分表示相对于当前目录的层级，例如 `project/src`。
- 如果文件直接在所选文件夹根下，则 `relativePath` 只有文件名，例如 `README.md`。

### 3. 后端路径解析与文件夹创建

- 后端新增路径解析逻辑：根据当前 `parentId` 和 `relativePath` 的目录部分，逐层查找或创建文件夹。
- 使用用户级 Redisson 写锁，保证同一用户并发上传同一文件夹时不会重复创建或冲突。
- 文件夹同名时直接复用已有文件夹（合并）。
- 路径创建成功但文件初始化失败时，已创建的文件夹保留，不主动回滚。

### 4. 路径安全

- 对 `relativePath` 做规范化并拒绝包含 `..` 段的路径，防止路径穿越。
- 路径中的每一段均按现有文件名/文件夹名规则校验，禁止包含 `/`、 `\` 等非法字符。
- 限制路径深度，防止异常深层路径导致性能问题。

### 5. 冲突处理

- 文件夹冲突：统一按递归合并处理，不弹窗、不报错。
- 文件冲突：文件夹上传场景默认使用 `keep`（自动重命名），不弹出批量冲突弹窗。
- 普通多文件上传保持现有行为，仍可通过批量冲突弹窗逐项选择策略。

### 6. 秒传与预检

- 扩展 `/files/upload/pre-check` 支持 `relativePath`。
- 后端先解析出最终目标目录，再在该目录下执行冲突检测与秒传候选查询。
- 秒传逻辑继续生效：找到候选且完整 hash 校验通过后直接创建文件节点。

### 7. 空文件夹

- 浏览器 `webkitdirectory` 不会返回空文件夹，只能拿到包含文件的文件夹。
- 产品层面接受空文件夹在上传过程中丢失。

### 8. 前端上传链路

- 扩展 `useBatchUpload`：支持传入带 `relativePath` 的文件列表，并允许调用方指定 `defaultConflictStrategy`。
- 文件夹上传时传入 `defaultConflictStrategy: 'keep'`，跳过冲突弹窗。
- 内部仍调用 `useChunkedUpload` 完成分片上传，保持暂停、断点续传、进度展示等能力不变。

## 影响

- 后端需要修改 `FileUploadPreCheckDto`、`ChunkedUploadInitDto`，并在 `FileServiceImpl` 与 `ChunkedUploadServiceImpl` 中增加路径解析与文件夹自动创建逻辑。
- 分片上传初始化需要加用户级写锁，与现有上传/完成流程保持一致。
- 前端需要扩展 `useBatchUpload` 与 `useChunkedUpload`，并在 `FileListToolbar` 中增加文件夹选择输入框、移除离线下载占位项。
- 需要补充单元测试覆盖：路径解析、文件夹合并、空路径（文件在当前目录）、路径安全校验、默认 `keep` 策略。
