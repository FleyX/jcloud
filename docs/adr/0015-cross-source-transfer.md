# 跨来源传输：本地与远程挂载互操作

远程挂载首期拒绝一切跨来源写操作。本次放开复制与移动（含文件夹递归），覆盖本地↔远程与远程↔远程（不同挂载点）两个方向。由于跨来源时字节必须经过服务器中转，执行模型定为「预检同步 + 执行异步」：预检复用两阶段冲突解决（远程目标的同名冲突基于本地镜像检测，执行时复查远端），执行阶段为异步传输任务，逐文件中转（源端下载 → 目标端上传）。

**关键决策：**

- **跨来源移动 = 复制 + 删源**，与同来源移动（仅改元数据）本质不同。以单文件为原子单元：复制成功才删该文件的源；删除源遵循各来源现有删除语义（本地源进回收站，远程源按远程写回真删）。部分失败时其余文件继续，任务结果记为成功/部分成功/失败并记录明细。
- **远程→本地仅校验配额与存储空间容量，不做秒传去重**（远程 etag 与本地文件身份 Hash 不可比，边下边算 hash 再去重收益不抵复杂度）。
- **本地→远程写回成功后立即创建本地 FileNode 镜像**，不依赖下次同步。
- **锁粒度：预检持用户级读写锁，执行阶段按单文件短锁 + 挂载点级锁**；不全程霸锁，避免大目录传输阻塞用户其他写操作与定时同步。
- **新建 `t_transfer_task` 表**持久化传输任务，不复用 `t_remote_sync_task`（同步是镜像对齐，传输是字节搬运，语义与字段均不同）。
- **支持取消**：任务置为取消中，当前文件传完后停止，已传输部分保留不回滚。
- **WebDAV 的 COPY/MOVE 跨来源同步放开**，走同一套传输机制。

**Considered Options：**

- 全同步执行（单请求内完成传输）——大文件/目录必然超时，失败无法恢复，否决。
- 整体原子 + 失败回滚——回滚本身可能失败，且与回收站/真删语义交织，复杂度远高于单文件原子，否决。
- 复用 `t_remote_sync_task` 表——省一次 DDL 但语义混杂，否决。

**Consequences：**

- 远程挂载「冲突策略：以远程为准」与传输任务交错时，执行阶段复查远端兜底，可能出现用户预检后远端已变更导致的单文件失败，体现在失败明细中。
- 前端复用现有复制/移动入口，目标为异来源时自动转为传输任务，通过轮询任务状态展示进度。
