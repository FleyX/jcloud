# 影视媒体库模型重构（多来源目录 + Jellyfin 风前端）

决定将影视模块的「视频目录」升级为「媒体库」：一个媒体库 = 名称 + 媒体类型 + N 个来源目录（子表 `t_media_directory_source`），并将前端信息架构改为 Jellyfin 风格（隐藏二级菜单，影视首页含我的媒体 / 继续观看 / 接下来，详情页按季展示）。项目尚未正式上线，不做历史数据迁移。

## 关键决策

1. **媒体库 + 来源目录子表**：`t_media_directory` 保留为媒体库主表，新增 `t_media_directory_source`（`directory_id + file_node_id`），原 `file_node_id` 字段删除。拒绝用 JSON 数组存多个目录——来源目录需参与扫描 diff、删除联动等查询。
2. **媒体类型创建后不可修改**：前端置灰 + 后端校验双重拦截，填错只能删除重建。避免类型变更时「保留手动匹配与播放进度」的复杂迁移语义。
3. **文件变更哈希纳入来源目录维度**：哈希输入改为 `来源目录 ID + 相对路径 + 文件名 + 文件大小`，避免多来源下同路径文件撞键。
4. **三层结构按来源目录独立套用，同名剧跨来源合并**：每个来源目录独立走 `来源目录 / 剧 / 季 / 集` 解析；同名剧按现有 `用户+剧名唯一` 规则合并为一部剧（对齐 Jellyfin 行为）。
5. **增删来源目录 = 中断任务 + 全量重扫**：统一语义，不为新增来源单独做增量扫；移除来源目录时其条目与播放进度一并清除。
6. **侧边栏隐藏做成通用能力**：一级模块级 `hideSidebar` 配置，PC 侧边栏与移动端抽屉同步响应，影视模块首期使用；不为 media 写特例。
7. **取消跨目录聚合海报墙**：删除 movies/series/others 聚合路由，海报墙改为按媒体库进入（`/media/libraries/:id`），对齐 Jellyfin；移动端同步改造，不留双架构。
8. **首页聚合接口**：新增 `GET /media/home` 一次返回我的媒体、继续观看（进度 0~95%，含电影/剧集/其他，按最后播放时间倒序）、接下来（仅电视剧，每剧第一集未看完的集，排除在播集）三段数据。看完阈值沿用 95%。
9. **剧集详情页按季展示**：页内两态（季卡片 ↔ 某季剧集列表，`?season=N` 保状态），剧集按季懒加载；未识别季显示「未知季」排最后（Jellyfin 同款行为）。

## 后果

- 「视频目录」术语在 CONTEXT.md 中已被「媒体库」「来源目录」取代，相关词条（扫描、削刮、剧集归属、文件变更哈希）同步改写。
- 媒体库删除时级联清除条目、播放进度与剧/季孤儿数据，物理文件不动。
