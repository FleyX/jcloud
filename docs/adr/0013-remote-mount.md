# 远程资源挂载架构

决定在 jcloud 中引入远程资源挂载能力：用户在个人文件树的一级目录下创建远程挂载点，首期支持 WebDAV，并通过策略模式预留 S3、NFS 扩展。远程目录的元数据会同步到本地 `t_file_node`，以支持搜索与浏览；写操作实时回写远端，冲突以远程为准。

## 关键决策

1. **挂载点作为特殊 FileNode**：远程挂载点是用户虚拟文件树根节点下的一级文件夹，`source_type = 'remote'`，拥有独立的挂载点级操作语义（删除=取消挂载，重命名只改本地显示名）。
2. **本地与远程用同一 FileNode 表区分**：新增 `source_type`（`local` / `remote`）和 `remote_mount_id`；`storage_space_id` 仅用于本地文件。远程文件不计入用户配额与本地存储空间容量。
3. **全量镜像 + 增量同步**：首次同步等价于本地镜像为空的全量同步；后续基于远程元数据（WebDAV 的 `etag` 存于 `hash` 字段，`last_modified` 复用现有字段）做增量 diff。
4. **双向写回，远程为准**：远程目录内支持删除、重命名、移动、上传、新建文件夹，并实时回写 WebDAV；远端调用失败时本地变更立即回滚。同步阶段若出现冲突，远程状态覆盖本地。
5. **跨来源写操作拒绝**：任何源路径或目标路径跨越 `local` / `remote` 的写操作（包括混合目录的文件夹上传）首期统一拒绝。
6. **远程文件不进本地回收站**：删除即永久删除；取消挂载只删本地镜像，不删远端数据。
7. **并发控制**：每个远程挂载点使用独立的分布式锁，串行化同步任务与远程写回；本地 FileNode 更新仍走现有用户级写锁。
8. **远程分享限制**：分享禁止本地与远程文件混合；远程分享仅支持浏览和单个文件下载，不支持打包或下载整个分享。
9. **协议策略抽象**：定义 `RemoteProtocolAdapter` 接口（list、download、upload、delete、move、createFolder 等），首期实现 WebDAV 适配器。
10. **预览缓存**：远程文件下载不缓存，预览图可缓存于系统数据目录，缓存键包含 etag 并在 etag 变化时失效。
