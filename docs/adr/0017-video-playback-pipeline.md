# 视频播放链路：探测入库 + 直放 / 实时 HLS 转码

视频媒体库的播放采用「探测入库 + 双链路播放」：扫描时用 ffprobe 将每个视频的封装、视频/音频编码、时长探测入库；播放时后端结合浏览器能力判定——可原生硬解的（如 MP4/H.264/AAC）走 Range 流式直放，不可硬解的由后端 ffmpeg 实时转码为 HLS（fMP4 切片）边转边播。转码优先使用硬件加速（VAAPI/QSV/NVENC，auto 模式自动探测且启动失败回退软解；硬解方式/设备/线程可在「系统 → 影视」配置，显式指定的硬解失败直接报错，见 0018）；全局并发转码进程数默认等于 CPU 核心数，可配置，转码会话空闲超时自动回收。

## Considered Options

- **后台预转码**：把所有不可硬解的视频提前转成统一格式。首开无转码延迟，但大量视频可能永不被看，磁盘与转码算力浪费严重，被排除。
- **实时转码为渐进式 MP4**：实现比 HLS 简单，但 seek 体验差、无法边转边切片缓存、无法灵活适配，被排除。

## Consequences

- ffprobe 探测成为扫描的必要步骤，远程挂载目录下的视频也需流式探测（只读文件头）。
- 转码会话需要独立的生命周期管理（HLS 输出目录、空闲回收、seek 重启进程）。
- Docker 部署需映射 `/dev/dri` 才能使用 VAAPI 硬件加速。
