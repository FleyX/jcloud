# 影视媒体库模型重构：库级归属 + 标题级实体 + 批次扫描清理

影视媒体库的剧记录是用户级共享实体，并发扫描下被用户级孤儿清理竞态删除，导致剧集《金部长的梦想人生》从海报墙消失且重扫无法自愈。决定重构底层数据模型：所有媒体实体改为库级归属，电影/剧集/集升级为标题级实体并配独立文件明细表，通过文件夹/文件节点锚定与批次扫描时间三道闸清理根治竞态与不自愈问题。项目尚未正式上线，旧四表废弃重建，不做历史数据迁移。

## 背景

本次重构由一次真实故障触发：剧集《金部长的梦想人生》从海报墙消失，重扫无法恢复。排查根因：

- **并发清理竞态**：剧记录是用户级共享实体（按用户+剧名唯一），孤儿清理 `cleanupOrphans` 也是用户级。多个媒体库并发扫描时，一个库的清理会删掉另一个库「刚创建、还没挂上集条目」的剧记录；无外键约束，删除静默成功，产生指向已删除剧的孤儿集条目。
- **损坏不自愈**：未变更文件在重扫时被整体跳过，条目与剧的归属关系一旦损坏永不修复，剧集从海报墙永久消失。
- **空壳剧删-建循环**：扫描还会为「全跳过文件的剧」创建空壳剧记录，与孤儿清理形成删-建循环，数据反复震荡。

## 关键决策

1. **库级归属**：电影/剧集/季/集/其他与文件明细、元数据全部归属媒体库（同名内容跨库各建一条），清理在库内闭环，根除跨库竞态。`user_id` 冗余存储便于按用户清理。
2. **标题级实体 + 两张明细表**：电影、剧集、其他分三张顶级表；集为标题级（`(season_id, episode_no)` 唯一键），季独立成表；电影文件、集文件为文件级明细表。条目表不再混装文件事实与标题级概念，多版本不再重复上墙。
3. **文件夹/文件节点锚定 + 改挂**：剧/季/电影行锚 = 文件夹 `file_node_id`，明细行/其他行锚 = 视频文件 `file_node_id`，均唯一约束；集行以唯一键为身份。重命名仅更新标题字段（manual 保留、非 manual 重置），移动按锚改挂到新父级，播放进度与手动修正不丢失。
4. **批次扫描时间清理三道闸，取代 `cleanupOrphans`**：即时 reconcile 负责亲眼确认的增删改；批次清理仅在完整成功（`COMPLETED`）的扫描末尾执行（①），按来源目录结算清理资格、仅限本轮可达且完整扫完的来源（②），且只删 `scan_time` 早于批次时间的顶级行并级联（③）。远程挂载掉线、扫描中断/部分失败均不误删。
5. **元数据一对一 + owner 反向指针**：`t_media_metadata` 增加 `owner_type`（movie/series/season/episode）+ `owner_id` 反向指针，删除条目时元数据行在应用层事务内级联清理，孤儿可排查可清理。
6. **`metadata_complete` 可扩展校验**：布尔标志仅挂电影/剧集行，判定实现为可扩展的有序校验项列表（字段谓词 + 标识），首版 5 项：标题、简介、海报、发行日期、评分；每次削刮后重算。剧集行为聚合语义：剧自身元数据完整且所有实际存在的季、集都完整才算完整。
7. **`match_status` 仅电影/剧集行，集级手动修正下线**：季、集不挂匹配状态，集元数据完全由剧级匹配派生；`manual` 永不覆盖语义不变，削刮处理范围从「仅 unmatched」扩展为「unmatched 或 metadata_complete = false」的非 manual 行。
8. **严格结构规范**：电视库严格三层「来源目录/剧/季/集」，剧文件夹下散落视频直接丢弃（取消「归入 S01」）、无虚拟季；电影库「直接包含视频的目录即一部电影」，中间层级不限、来源根目录散文件丢弃、Jellyfin extras 目录名清单跳过；同一电影文件夹内多视频一律按多版本聚合（v1 不做 cd/part 分片连播）；其他库每文件一行，行为与现状一致。实施补充（#18）：自顶向下识别，祖先已是电影文件夹的目录不再递归——电影文件夹内嵌套的含视频子目录（非 extras）不单独成条目、其视频不入库，与电视库「超三层忽略」同义，保证「一部电影一个文件夹」可预期。
9. **外部字幕关联文件明细行**：`t_media_subtitle` 的关联对象从旧条目改为文件明细行。
10. **旧四表 drop，不迁移**：废弃 `t_media_item`、旧 `t_media_series`、旧 `t_media_season`、旧 `t_media_metadata`，单个 Flyway 迁移文件重建 8 张新表，重扫重建数据。

## 考虑过的备选方案

- **保留用户级共享剧记录**：竞态与删-建循环的根源，只能靠串行化掩盖，否决。
- **文件级实体**（每视频一行、无标题级）：剧名/季集号/匹配状态等标题级概念无处安放，多版本在海报墙重复出现，否决。
- **清洗名+年份聚合键**替代文件夹锚定：重命名/移动即丢失进度与 manual，同名内容聚合不可控，否决。
- **Jellyfin 混合散文件方案**（目录与散文件共存成条目）：与「每部电影一个文件夹」规范冲突，产生散文件垃圾条目，否决。
- **用户级扫描锁**：仅串行化扫描缓解症状，牺牲并发（同用户多库串行），且不修复不自愈问题，否决。
- **`cleanupOrphans` 改库级**：仍依赖「重建后重扫」的脆弱时序，无法根治删-建循环，否决。

## 后果

- **播放进度清零**：旧四表废弃，历史播放进度不迁移，重扫重建（未上线，可接受）。
- **电影/剧集散文件需整理**：电影来源根目录散文件、剧文件夹下散文件将直接丢弃，既有散文件库需手工整理成规范目录结构。
- **集级手动修正功能下线**：对应接口移除，集元数据完全由剧级匹配派生。
- **前端/查询接口重写**：海报墙、详情、搜索、排序按新实体重写，电影详情与播放器增加版本选择，移除集级修正入口。

## 与旧 ADR 的关系

本 ADR 取代 0019/0020 中与新模型冲突的部分：0019 的「同名剧跨来源合并（用户+剧名唯一）」、「散文件归入 S01」等描述作废；0020 的「元数据绑定 `t_media_item`/剧/季、集元数据挂集条目」作废，元数据改为一对一 + `owner_type`/`owner_id` 反向指针。0019 的媒体库 + 来源目录子表、0020 的 NFO 本地优先与写回机制等与新模型兼容的部分继续有效。CONTEXT.md「视频媒体库领域」已按新模型同步改写。
