# 影视元数据模型重构：NFO 机制 + 元数据按用户隔离

> **状态**：第 4 条的图片命名约定已被 ADR 0022 部分取代（识别别名集 + 写回改 `folder.jpg`/`backdrop.jpg`）；其余决策仍然有效。

影视削刮升级为 Jellyfin 兼容的 NFO 机制后，元数据的权威来源从「TMDB 唯一」变为「本地 NFO 优先、TMDB 兜底」。本地 NFO 可能没有 tmdb_id、字段任意残缺，与「tmdb_id+类型全局共享缓存」模型根本冲突，因此决定废弃共享缓存：媒体元数据按用户隔离，每条直接绑定到电影条目/剧/季。项目尚未正式上线，不做历史数据迁移。

## 关键决策

1. **元数据按用户隔离，废弃全局共享缓存**：`t_media_metadata` 增加 `user_id`，不再以 `tmdb_id+类型` 去重；电影条目、剧、季通过各自 `metadata_id` 直接持有自己的元数据（季/集元数据同样隔离，季挂 `t_media_season`、集挂集条目）。TMDB 来源的元数据同样放弃共享——两个用户收录同一影片各拉各存。拒绝「nfo 隔离 + TMDB 共享」的混合模型：两种键控与生命周期并存会让刷新/清理逻辑分叉。
2. **本地 NFO 完全信任，不请求 TMDB 补全**：削刮为本地优先——同目录存在 NFO/本地图片即用本地内容，即使无 tmdb_id、字段残缺也不回源 TMDB；元数据带 `source`（`local_nfo`/`tmdb`）与完整性状态标记，不完整不补。本地缺失时才走现有 TMDB 搜索匹配。变更感知不做文件监控，削刮时现读现用，用户改 nfo 后重新削刮即生效。
3. **削刮成功即写回，本地远程都写（local_nfo 跳过）**：自动削刮与手动修正成功后，立即将元数据写回视频所在目录的 NFO 与图片（远程挂载来源经协议适配器写回）；各级元数据来源为 `local_nfo` 时该级跳过写回——内容为用户提供、已在视频目录，规范化重写只会丢失 actor/uniqueid/studio 等 Jellyfin 字段。落盘失败不影响元数据入库，仅记录待重试——远程抖动不拖垮削刮主流程。
4. **Jellyfin 命名约定，三级全写**：电影/集为与视频同名的 `.nfo`，剧文件夹为 `tvshow.nfo`；图片为 `poster.jpg`、`fanart.jpg`、`season01-poster.jpg`。剧级（tvshow.nfo+海报/背景）、季级（季海报）、集级（集 nfo）全部写回，Jellyfin 挂同一目录后完全免削刮。
5. **NFO/图片作为普通 FileNode 入库**：文件树可见、计配额、走正常同步链路。拒绝「只写物理文件不入库」——本地用户同步与远程同步都会把未登记的物理文件自动导入文件树，不入库反而要多维护一套排除规则。视频删除时 nfo/图片作为独立文件不级联清理。
6. **图片按需从视频目录读取，不进系统缓存**：`t_media_metadata` 改存海报/背景的 FileNode 引用，poster/backdrop 接口实时读取（本地直读，远程经适配器下载，响应加缓存头缓解）。拒绝复制进系统数据目录——与「图片保存在视频目录供 Jellyfin 使用」的目标重复占盘。
7. **同步后触发媒体库扫描**：用户管理中的文件同步（手动+cron）与远程挂载同步完成后，自动触发该用户所有媒体库扫描，复用现有同库扫描合并与扫描/削刮互斥机制，扫描完成沿用级联非强制削刮。

## 后果

- CONTEXT.md 已同步改写「媒体元数据」「削刮」「季/集元数据」词条，新增「NFO 文件」「本地媒体图片」「同步后扫描」。
- 全局共享缓存相关的去重、补抓逻辑（如启动时 backdrop 补抓）需按隔离模型重写；多用户重复拉取同一影片会增加 TMDB 调用量，由用户侧削刮时机自然限流，不引入额外机制。
- 远程挂载来源的海报墙图片每次请求经 WebDAV 实时下载，性能代价已确认接受。
