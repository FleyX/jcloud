# 移动端顶部栏、二级菜单抽屉与个人中心页设计

针对移动端当前暴露出的两个问题——底部 Tab 只能进入每个一级模块的第一个二级菜单、没有 Logo 和个人信息入口——我们决定为移动端增加固定顶部栏和左侧二级菜单抽屉，并把个人相关操作收敛到独立的个人中心页。

## 背景与取舍

### 问题 1：底部 Tab 无法承载二级菜单

当前 `MobileBottomNav.vue` 把每个 Tab 绑定到一级模块的第一个二级菜单路由。例如「系统」Tab 永远跳转到 `/admin/users`，用户进入后没有 UI 可以切换到「角色」「权限」。

考虑过三种方案：

1. **底部 Tab 直接列出所有二级页面**：把「用户」「角色」「权限」都放到 TabBar。这会破坏一级模块的聚合语义，且 Tab 数量会随功能膨胀。
2. **为每个模块增加二级横向 Tab**：在顶部栏下方再加一排分段控制器。会严重挤压主内容区高度，且与顶部栏标题的语义重复。
3. **保持底部 Tab 为一级模块，增加二级菜单抽屉**：底部 Tab 只负责切换一级模块，点击顶部栏标题展开当前模块的二级菜单抽屉。保留了一级/二级分层语义，也解决了切换问题。

选择方案 3。

### 问题 2：Logo 与个人信息没有入口

当前 `MobileAppShell.vue` 只有主内容区和底部导航，没有任何顶部区域。所有用户相关能力（头像、用户名、退出、修改密码）在移动端都不可达。

考虑过三种方案：

1. **在底部 Tab 增加「我的」Tab**：把个人中心提升到一级模块。但个人相关操作不是核心业务模块，与「文件」「系统」并列会稀释导航语义。
2. **在二级菜单抽屉里放用户信息**：把头像和退出放在抽屉底部。这会把用户全局状态隐藏得太深。
3. **增加固定顶部栏**：顶部栏左侧放 Logo，中间放当前模块标题（打开抽屉），右侧放头像（进入个人中心页）。信息层级清晰，也解决了抽屉入口问题。

选择方案 3。

## 关键决策

- **底部 Tab 继续代表一级模块**：每个 Tab 对应一个 `PrimaryModule`，路由目标为该模块的第一个二级菜单。一级模块的切换语义与 PC 端顶部导航保持一致。
- **底部 Tab 高亮由路由反查**：不再用 `route.path.startsWith(tab.route)` 匹配第一个二级菜单，而是遍历 `menuStore` 中各模块的二级菜单，找出当前路由所属的一级模块，从而高亮对应 Tab。
- **增加固定移动顶部栏**：在 `MobileAppShell.vue` 中增加固定顶部栏，高度与 PC 端一致（`h-14`），左侧为图标-only Logo，中间为当前一级模块标题，右侧为用户头像。
- **Logo 点击返回首页**：点击左侧 Logo 回到默认首页（`files` 模块的第一个二级页面）。在个人中心页等无一级模块归属的页面，左侧替换为返回箭头。
- **模块标题打开二级菜单抽屉**：点击顶部栏标题，从左侧滑出抽屉，展示当前一级模块下的全部二级菜单；选中后关闭抽屉并导航。
- **头像进入个人中心页**：点击顶部栏头像，进入独立的 `/profile` 页面，展示当前用户信息，并提供「个人信息」「修改密码」「退出登录」入口。
- **复用现有 Dialog 组件**：`ProfileDialog.vue` 与 `ChangePasswordDialog.vue` 已基于 `radix-vue` 实现，宽度自适应，可在移动端复用。为消除 PC/Mobile 目录歧义，将它们迁移到 `src/components/user/` 共享目录。

## 影响

- `MobileAppShell.vue` 的 DOM 结构从「主内容区 + 底部导航」变为「顶部栏 + 主内容区 + 底部导航」。主内容区继续通过 `flex-1 overflow-y-auto` 滚动，顶部栏与底部导航固定不动。
- `MobileBottomNav.vue` 需要新增路由反查逻辑，确保在任意二级页面下 Tab 高亮正确。
- 需要新增 `MobileHeader.vue`、`MobileDrawer.vue`（或等效组件）以及 `views/mobile/user/Profile.vue`。
- `ProfileDialog.vue` 与 `ChangePasswordDialog.vue` 从 `views/pc/user/components/` 迁移到 `src/components/user/`，PC 端 `Header.vue` 同步更新引用路径。
